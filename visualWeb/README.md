# VisualWeb — VS Code 프론트엔드 디자이너

시각적으로 폼을 설계하고 Next.js + React 프론트엔드 프로젝트를 생성합니다. DB 접근과 JSON API는 Spring Boot 기반의 별도 `../backend/` 서버에서 담당합니다. 관리자 기능은 추후 `../admin/`에서 개발할 예정입니다. 현재 디자이너는 VisualWeb 설계 JSON을 편집하며, 기존 React/Next.js 소스 코드를 분석해 설계로 변환하거나 수정 내용을 기존 소스에 병합하지 않습니다.

## 구성

- `extension/src/`: VS Code 확장, 설계 모델, 생성기와 CLI
- `extension/media/`: 시각 디자이너
- `extension/templates/`: 프론트엔드 및 API 프록시 템플릿
- `extension/examples/`: 예제 `*.visualweb.json`
- `frontend/`: 템플릿에서 재생성하는 예제 앱 (직접 수정하지 않음)
- `scripts/regenerate-example.cjs`: 예제 재생성 및 동기화 검사
- `Samples/`: 분리 전 생성한 기존 예제 (백엔드 포함, 자동 변경하지 않음)

## 확장 실행

VS Code에서 `visualWeb/` 폴더를 열고 실행 및 디버그(Ctrl+Shift+D)에서 **Run VisualWeb Extension**을 선택한 뒤 F5를 누릅니다. 새 Extension Development Host 창에는 빈 디자이너가 열립니다. **폴더 불러오기**로 VisualWeb 프로젝트를 선택하거나 `extension/examples/members.visualweb.json`을 엽니다. JSON으로 열리면 파일 탭에서 **Reopen Editor With… → VisualWeb Designer**를 선택합니다. 새 설계는 명령 팔레트의 **VisualWeb: 새 프로젝트**로 만들 수 있습니다. 편집한 뒤 저장하고 **Save As...**을 선택하면 앱을 생성합니다. 생성 대상은 새 폴더여야 합니다.

## 샘플 앱 실행

Node.js 20.9 이상이 필요합니다. 이 디렉터리에서:

```bash
npm install
npm run example:generate
cp frontend/.env.local.example frontend/.env.local
npm run dev
```

`frontend/.env.local`의 `VISUALBACK_URL`을 백엔드 주소로 설정하고 VisualBack을 별도 실행하세요. 기본 프론트엔드는 `http://localhost:3000`, 백엔드는 `http://127.0.0.1:4000`입니다. 브라우저 요청은 Next.js API 프록시를 거쳐 백엔드로 전달됩니다. 프론트엔드는 DB 코드와 비밀번호를 포함하지 않습니다.

## 예제 재생성

예제의 원본은 `extension/examples/members.visualweb.json`과 `extension/src/generator.js`, `extension/templates/`입니다. 화면과 생성 로직은 원본에서 수정하고 아래 명령으로 반영합니다.

```bash
npm run example:generate  # frontend/ 재생성
npm run example:check     # 원본과 예제가 일치하는지 검사
```

`frontend/`의 생성 파일은 직접 편집하지 않습니다. 재생성은 생성 파일 목록(`frontend/.visualweb-generated.json`)으로 관리하며, 목록에 있던 오래된 생성 파일은 제거합니다. `.env.local`, `.next/`, 설치된 의존성과 기타 파일은 보존합니다. 일반 CLI와 확장의 프로젝트 생성은 계속 새 폴더에만 수행합니다.

## 검증 및 CLI

```bash
npm test
npm run example:check
npm run check --prefix extension
npm run build
node extension/test/browser.cjs
node extension/src/cli.js extension/examples/members.visualweb.json /tmp/new-visualweb-app
```

브라우저 테스트는 로컬 Chrome을 사용합니다 (`CHROME_PATH` 지정 가능). VS Code 메시지 브리지는 모킹하므로 실제 저장·Undo/Redo·내보내기는 F5로 확인하세요. 생성된 `frontend/schema.json`과 VisualBack의 모델 및 DB 테이블을 일치시켜야 합니다.

VisualBack 예제 백엔드는 회원(name/email) 모델의 등록·조회·수정·삭제 API를 제공합니다. VisualWeb 설계에 따라 Java API나 DB 스키마를 자동 생성하지 않으므로 다른 모델에는 별도 DTO·서비스·마이그레이션 구현이 필요합니다. 백엔드 API 테스트는 Java MockMvc로 작성했습니다.

## 컴포넌트 배치

왼쪽의 Button, Input, Text, Container, Grid를 드래그해 추가합니다. 캔버스에서는 드롭 좌표로 자유롭게 배치하고, Container 및 Grid 셀 안에서는 삽입 영역으로 순서를 바꿉니다. Container는 Flow Layout으로 가로에 순서대로 배치하고 남는 폭이 부족하면 다음 줄로 넘어갑니다. Grid는 헤더와 바디를 구분하는 표입니다. 디자이너는 1~6개의 바디 미리보기 행과 1~4열의 셀 템플릿을 편집하며 각 셀에 Text 또는 컴포넌트를 배치합니다. 생성된 앱의 헤더 제목·열 순서·행 수·값은 `/api/grid` 응답을 사용합니다. 디자이너 헤더는 예시이며 실행 시 백엔드 값으로 대체됩니다. 내용이 있는 셀을 삭제하는 축소는 먼저 내용을 이동해야 합니다.

오른쪽 속성에서 텍스트, 입력 필드, 버튼 동작과 레이아웃을 수정합니다. 일반 Button은 동작을 자동 생성하지 않으며 폼 저장 Button은 API 제출을 실행합니다. Input이 없는 화면도 만들 수 있습니다. 캔버스 위치는 X·Y 좌표와 너비로 저장합니다. Container 안에서는 Flow Layout, Grid 안에서는 셀 배치를 따릅니다. 자유 배치 화면은 좌표를 유지하며 좁은 화면에서는 가로 스크롤합니다. 설계 파일의 `components` 트리를 저장하고 생성된 프론트엔드에도 같은 구조를 적용합니다. 기존 v2 필드 설계도 계속 열 수 있습니다.

Grid JSON은 Tabulator 형태의 `{"columns":[{"field":"name","title":"이름"}],"data":[{"id":1,"name":"Kim"}]}` 형식을 사용합니다. 컬럼 `field`로 바디 값을 연결합니다. 기존 `headers/rows` 형식도 읽을 수 있습니다. 빈 셀에는 백엔드 값을 바로 표시하며, Text의 **백엔드 셀 값 표시**를 체크하면 해당 위치의 값을 표시합니다. 체크하지 않은 Text와 Button은 디자인한 내용을 유지합니다. 바디 셀 템플릿은 미리보기 행 순서대로 반복하며, 템플릿보다 많은 백엔드 열은 값을 바로 표시합니다. 각 Grid는 화면의 기본 조회 API를 사용하거나 오른쪽 속성에서 별도 조회 API를 지정합니다.

Grid는 [Tabulator 5.6 예제](https://www.tabulator.info/examples/5.6/)를 참고한 자체 React 구현입니다. Tabulator 라이브러리 전체를 사용하는 것은 아닙니다. 헤더 클릭 정렬, 헤더 필터, 컬럼 손잡이 드래그 이동, 경계 드래그/방향키 너비 조절, 행 선택, 로컬 페이지 이동을 제공합니다. 오른쪽에서 높이·페이지 크기·정렬·필터·페이지 이동을 설정합니다. 디자이너의 헤더는 미리보기이며 데이터 조작은 생성된 앱에서 실행합니다. 서버 JSON의 실행 코드나 formatter는 실행하지 않습니다. 원격 페이지 이동, 셀 수정 저장, 다운로드와 그룹 헤더는 아직 구현하지 않았습니다.

캔버스 컴포넌트는 오른쪽의 X·Y·너비(px)로 조정하거나 드래그해 이동합니다. 격자는 표시 안내이며 강제로 스냅하지 않습니다. Container/Grid 셀로 옮기면 절대 좌표를 해제하고 해당 요소의 배치 규칙을 적용합니다. 기존 좌표 없는 설계는 겹치지 않는 기본 위치로 열립니다. 격자 표시 설정은 생성된 앱에 포함하지 않습니다.

Button은 **한 칸**과 **전체 너비** 모두 **버튼 위치**에서 왼쪽·가운데·오른쪽을 선택할 수 있습니다. 세로 정렬(위·가운데·아래), 배치 영역 높이, 가로·세로 이동량도 조정합니다. 이동량은 음수로 왼쪽/위, 양수로 오른쪽/아래로 이동합니다. 배치 영역은 전체 너비를 차지하고 버튼 자체는 텍스트 크기를 유지합니다. 자유 캔버스에서는 지정한 px 너비 안에서 정렬합니다.

## 미리보기

**미리보기 ▶**는 현재 설계와 최신 템플릿으로 별도의 미리보기 앱을 생성해 실행합니다. 저장 또는 불러온 프로젝트가 있으면 그 폴더의 환경 설정과 설치된 의존성을 재사용합니다. 원본 앱 코드는 덮어쓰지 않습니다. 아직 저장하지 않은 설계 변경과 새 워크스페이스 디자인도 미리보기에 반영됩니다. 수동 수정한 앱 코드 자체를 실행하려면 해당 프로젝트에서 `npm run dev`를 사용합니다.

아직 프로젝트를 생성하지 않았으면 현재 문서로 임시 미리보기 앱을 만듭니다. 이때 `visualweb.preview.backendUrl` 설정을 사용하며, 설치된 개발 의존성이 있으면 재사용합니다. 원격/가상 저장소 URI는 확장 호스트의 임시 폴더를 사용합니다.

설치된 의존성이 없는 프로젝트에는 `npm install`을 실행하므로 Node.js/npm과 최초 설치 시 네트워크가 필요합니다. 서버가 준비되면 VS Code Simple Browser에서 열며, 다시 누르면 실행 중인 서버를 재사용합니다. 디자이너를 닫으면 서버도 종료됩니다. 로그는 **출력 → VisualWeb Preview**에서 확인하세요. 데이터 조회·저장에는 실행 중인 VisualBack이 필요합니다.

생성된 화면에는 자동 등록 목록을 붙이지 않습니다. 데이터 표시는 직접 배치한 Grid에서만 제공하며, Grid가 있을 때만 `/api/grid`로 조회하고 저장 후 갱신합니다.

## 여러 화면과 탭 미리보기

디자이너 왼쪽 **프로젝트 화면 → 화면 추가**로 새 화면을 만들고 제목·컴포넌트를 편집합니다. 화면 목록에서 선택해 전환할 수 있으며 추가 화면은 삭제할 수 있습니다. 기본 화면은 기존 설계를 유지합니다. 프로젝트 JSON의 `screens`에 추가 화면을 함께 저장합니다.

생성된 앱과 미리보기는 남색 사이드바, 보라색 워크스페이스 헤더와 탭으로 구성됩니다. 왼쪽 메뉴는 프로젝트 화면 목록을 표시하고, 선택한 화면을 오른쪽 탭으로 엽니다. 이미 열린 화면은 기존 탭으로 전환하며, 탭을 닫아도 화면 설계는 삭제되지 않습니다. 열려 있는 탭의 입력 상태는 전환 중 유지됩니다. 화면별 API 관리에서 여러 API 경로를 등록할 수 있습니다. 서버 주소는 VISUALBACK_URL 환경변수로 설정합니다. 이미 생성한 프로젝트에는 다시 생성해 적용하세요.

## 이전 프로젝트 불러오기

디자이너의 **폴더 불러오기** 또는 명령 팔레트의 **VisualWeb: 프로젝트 폴더 불러오기**에서 이전에 생성한 프로젝트의 루트 폴더를 선택합니다. 화면 목록과 컴포넌트 배치를 복원하고 **미리보기**는 선택한 프로젝트의 설정을 사용하고 현재 설계를 최신 워크스페이스 디자인으로 실행합니다.

새로 생성되는 프로젝트에는 편집 원본인 `project.visualweb.json`이 포함됩니다. 이전 프로젝트에 이 파일이 없으면 `frontend/schema.json`을 읽어 편집 원본을 추가합니다. 기존 앱 코드와 환경 설정은 변경하지 않습니다. 디자인 수정은 Ctrl/Cmd+S로 저장하며, 생성 코드에 반영하려면 프로젝트를 다시 생성합니다. 앱 코드를 수동 수정한 내용은 설계로 역변환하지 않습니다.

왼쪽 메뉴의 **라디오박스**, **셀렉트박스**, **텍스트에어리어**도 캔버스·Container·Grid 셀에 배치할 수 있습니다. 라디오/셀렉트의 선택 항목은 오른쪽에서 한 줄에 `값|표시 이름` 형식으로 편집합니다. 텍스트에어리어는 표시 행 수(2~20)를 지정합니다. 라벨·API 필드 이름·필수 입력도 편집할 수 있으며 폼 제출 시 선택/입력한 문자열을 전달합니다. 새로운 필드의 실제 저장 처리는 해당 VisualBack DTO와 DB 스키마에 맞춰 구현해야 합니다.

Grid 셀 안의 Button도 직접 클릭해 선택하고 오른쪽 **버튼 텍스트**에서 개별 이름을 수정합니다.

## VisualBack API 연결 UI

프로젝트를 불러온 뒤 왼쪽 **API 관리** 버튼으로 팝업을 엽니다. 팝업의 **API 추가**로 이름·GET/POST/PUT/PATCH/DELETE 메서드·경로를 여러 개 등록합니다. **적용**은 변경을 반영하고 **취소**는 팝업에서 수정한 내용을 버립니다. 예: `/api/members`, `/api/members/grid`. 서버 주소는 `frontend/.env.local`의 `VISUALBACK_URL`을 사용합니다. 설계 파일에 남아 있는 이전 서버 주소는 사용하지 않습니다. 화면을 전환하면 해당 화면의 연결 설정을 편집합니다.

폼 저장 버튼이나 Grid를 선택하면 오른쪽 **연결할 API**에서 팝업에 등록한 API를 선택합니다. 버튼은 등록한 HTTP 메서드, Grid는 GET API를 사용합니다. 기본 설정을 선택하면 직접 경로를 입력할 수도 있습니다. 사용 중인 API는 컴포넌트 연결을 바꾼 뒤 삭제할 수 있습니다. 빈 값은 화면 설정을 따릅니다. 요청 JSON 키는 입력 컴포넌트의 **API 필드 이름**을 사용하며 숫자 필드는 JSON 숫자로 전송합니다. 상단 **저장하기** 또는 Ctrl+S로 열린 폴더의 `project.visualweb.json`을 업데이트한 뒤 미리보기 또는 새 프로젝트 생성으로 적용합니다. 이미 생성한 앱에는 재생성해서 적용하세요.

VisualBack 샘플 API의 응답은 `success`, `message`, `data` 구조를 사용합니다. Grid는 `data` 안의 `columns`와 `data` 행 배열을 읽습니다. 생성된 화면은 API 응답에 최상위 `pageNo`, `totalCount`가 있으면 이전/다음 버튼으로 `page`, `size`를 전달하는 서버 페이지 이동을 사용합니다. 이 메타데이터가 없으면 받은 데이터에 로컬 페이지 이동을 적용합니다. 정렬과 필터는 현재 받은 데이터에 적용합니다. 샘플 VisualBack의 `/api/grid`는 페이지 메타데이터를 반환하지 않으므로 원격 페이지 이동을 사용하려면 이를 지원하도록 API를 구현해야 합니다. API 요청은 생성된 Next.js 서버에서 프록시로 전달되므로 브라우저에서 VisualBack에 직접 접속하지 않습니다.

상단 **저장하기**는 현재 열린 설계 문서를 같은 경로에 저장합니다. **Save As...**은 별도 폴더에 앱 코드를 생성합니다. 입력 변경을 반영 중에 저장을 눌러도 반영 완료 후 저장합니다.

API 관리 팝업의 **사용 컴포넌트** 열에는 해당 API를 선택한 Grid/저장 버튼의 이름과 ID가 표시됩니다. 연결이 없으면 **미사용**으로 표시됩니다. ID는 오른쪽 컴포넌트 속성 상단에도 표시해 여러 컴포넌트를 구분합니다.


API 관리 팝업의 **요청 데이터 영역**에서 화면 전체, Container의 입력값 또는 Grid 선택 행을 지정합니다. Container 내부의 Input/Radio/Select/Textarea 값만 수집하며 필수 입력과 숫자 형식을 확인합니다. Grid 내부 버튼은 클릭한 행 전체를 JSON으로 보냅니다. Grid 외부 버튼은 지정한 Grid에서 선택한 행 전체를 보내며, 선택이 없으면 요청을 보내지 않습니다. GET 요청은 입력값을 Query로, 나머지 메서드는 JSON 본문으로 전송합니다. `/api/members/{id}`의 `{id}`는 요청 데이터에서 가져옵니다.

입력 컴포넌트를 선택한 뒤 오른쪽 **필수 입력**에서 `true`(필수) 또는 `false`(선택)를 설정합니다. JSON에는 boolean `required`로 저장됩니다. Input/Radio/Select/Textarea에 적용됩니다.

처음부터 설계하려면 디자이너 상단 **새 프로젝트**를 누르고 `.visualweb.json` 저장 위치를 선택하세요. 빈 캔버스에서 컴포넌트를 추가할 수 있습니다. 명령 팔레트의 **VisualWeb: 새 프로젝트**로도 시작할 수 있습니다. 기존 설계는 그대로 유지됩니다.

버튼을 선택하면 오른쪽 **버튼 너비 (px)**에서 40~2000px로 설정할 수 있습니다. 값을 비우면 자동 너비를 사용합니다. Container와 Grid 안의 버튼에도 적용됩니다.

**버튼 컨테이너 너비 (px)**는 버튼을 담는 배치 영역의 너비를 설정합니다(80~2000px). **버튼 너비 (px)**는 버튼 자체 크기이며 별도로 유지됩니다.
